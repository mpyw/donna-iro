# 変更を検証する

```sh
tools/check.sh
```

これだけ。終了コードが0なら通っている。**既定のビルドだけ見て「通った」と
報告しない。** feature を削った構成は静かに壊れる。

## なぜ組み合わせを回すのか

実装をファイルへ分けたとき、`mic` の `whisper` と `channel` の `window` の
cfg を落としていた。既定のビルドは通るので、5通り回していなければ
`--no-default-features` が壊れたまま出していた。

`pub` の監査でも同じことが起きた。`Cue::COUNT` は `embed` 系でしか使われ
ないので、既定ビルドの検査では非公開にできてしまい、`embed-reference` で
初めて落ちた。

## 読み方

| 行 | 意味 |
| --- | --- |
| `OK  0` | 通った |
| `OK  7（構成上の死にコード）` | 通った。機能を削ったぶん使われないものが死んでいるだけ |
| `警告` / `NG` | **落ちている。** 中身が下に出る |

**エラーはどの組み合わせでも失敗にする。警告は既定のビルドと埋め込みだけ
失敗にする。** 縮小ビルドの死にコードを0にするには `app` の側に `io` の
feature 名で cfg を書くことになり、層が濁るため。ただし数が増えたら見ること。

`embed-audio` / `embed` は本番音源（`assets/*.wav`）が無いと
`include_bytes!` が落ちる。スクリプトは音源があるときだけその組み合わせを
足すので、無い環境では出てこない。

## 落ちたとき

- **書式** → `cargo fmt`
- **エラー** → だいたい cfg の付け忘れか、可視性の絞りすぎ
- **警告（既定）** → 未使用の import は「その構成では要らない」の合図
